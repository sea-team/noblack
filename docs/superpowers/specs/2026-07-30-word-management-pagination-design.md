# 词库管理后端分页设计

## 背景

当前控制台进入“词库管理”时调用 `GET /words`，后端返回全部词条，前端将完整
数组保存在内存中并一次性生成全部表格行。合并词库约有六万余条记录，响应体、
JSON 解析和 DOM 创建都会占用大量内存，可能导致浏览器无响应或崩溃。

## 目标

词库列表由后端完成排序、搜索和分页，浏览器只接收并渲染当前页：

- 默认每页 50 条；
- 支持选择每页 20、50 或 100 条；
- 服务端允许的最大每页条数为 200；
- 支持按敏感词、等级和备注搜索；
- 新增、编辑、删除和文件重载后刷新当前页；
- 删除当前页最后一条时自动回到上一页；
- 不改变词库增删改接口、鉴权或持久化行为。

## API 契约

`GET /words` 接受以下查询参数：

| 参数 | 默认值 | 规则 |
|---|---:|---|
| `page` | `1` | 大于等于 1 的整数 |
| `page_size` | `50` | 1～200 的整数 |
| `q` | 空 | 去除首尾空白后的搜索词 |

示例：

```http
GET /words?page=2&page_size=50&q=赌博
```

不传分页参数时也只返回第一页 50 条，防止调用方意外获取完整词库。`page` 或
`page_size` 格式错误、超出范围时返回 HTTP 400。合法页码超过最后一页时返回
空 `words`，不视为错误。

成功响应：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "words": [
      {
        "word": "示例词",
        "levels": ["赌博"],
        "remarks": []
      }
    ],
    "count": 123,
    "page": 2,
    "page_size": 50,
    "total_pages": 3
  }
}
```

`count` 表示当前搜索条件下的匹配总数；`q` 为空时即为词库总条数。
`total_pages` 按 `count/page_size` 向上取整，匹配数为零时返回 0。

## 后端数据处理

`Store` 新增分页读取方法，在互斥锁保护下复制当前词条快照，随后释放锁，再执行
搜索、排序和切片，避免排序期间阻塞词库写操作。

搜索对敏感词、`levels` 和 `remarks` 做子串匹配。为了让英文搜索更符合后台
使用习惯，比较时统一转为小写；中文内容不受影响。结果继续按 `word` 升序排列，
保证翻页顺序稳定。

分页计算在存储层集中完成并返回：

```go
type EntryPage struct {
    Entries []matcher.Entry
    Total   int
}

func (s *Store) ListEntriesPage(page, pageSize int, query string) EntryPage
```

HTTP 层只负责解析、校验查询参数和组装响应，不再获取完整列表。

## 前端交互

词库页面维护当前页、每页条数、搜索词和服务端返回的匹配总数，不再保存
`ALL_WORDS`。

列表下方增加：

- 首页；
- 上一页；
- 当前页/总页数；
- 下一页；
- 末页；
- 每页 20、50、100 条选择器。

搜索输入停止输入 300 毫秒后请求后端，并重置到第一页。请求 URL 使用
`URLSearchParams` 构造，搜索词经过标准 URL 编码。

翻页请求进行中时禁用分页按钮，避免重复请求。若删除后当前页为空且页码大于
1，前端将页码减一并重新请求。新增、编辑和文件重载成功后保留搜索条件与每页
条数，并刷新当前页。

总数标题在无搜索时显示“词库列表（共 N 条）”，搜索时显示“词库列表（匹配
N 条）”。

## 兼容与文档

写接口保持不变。`GET /words` 从“返回全部”改为“默认返回第一页”，属于有意
的接口行为变化；API 文档、README 接口表和示例必须同步说明分页参数及响应
字段。

如外部调用方需要遍历全部词库，应按 `page` 和 `total_pages` 逐页请求，不再
提供隐式全量返回方式。

## 测试与验收

1. 存储层验证稳定排序、三字段搜索、页边界和空结果。
2. HTTP 层验证默认分页、自定义页、搜索及非法参数 HTTP 400。
3. 默认 `GET /words` 响应最多包含 50 条，不再返回全部词库。
4. 控制台不再包含 `ALL_WORDS` 或前端全量筛选逻辑。
5. 控制台包含分页控件、300 毫秒搜索延迟和服务端分页请求。
6. 新增、编辑、删除和重载后列表刷新规则正确。
7. Go、发布脚本和模型服务测试全部通过。
8. Linux、Windows 离线包重新编译，包内及外层 SHA-256 全部通过。
